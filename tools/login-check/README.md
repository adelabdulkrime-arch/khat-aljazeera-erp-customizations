# فحص صفحة الدخول قبل النشر

صفحة `/login` تُبنى فوق تنسيقات Frappe نفسه، وهي تخدم حزمتَي CSS (عربية وإنجليزية) بقيم معكوسة، وأربعة أقسام يبدّل بينها جافاسكربت، وحالات خطأ تُطيل البطاقة. تعديل يبدو سليماً في لقطة واحدة ينكسر في لغة أخرى أو مقاس آخر أو قسم آخر أو عند أول كلمة سرّ خاطئة. هذه الأدوات تفحص ذلك كلّه قبل أن يصل أي شيء للخادم.

## الملفات

| الملف | الدور |
|---|---|
| `serve.js` | معاينة محلية على `127.0.0.1:8765/login`: صفحة الموقع الحيّ كما هي، بملفات المستودع مكان ملفاتنا المنشورة |
| `checker.js` | يعرّف `__kajCheck()` (يعيد `{fails: [], info: {}}`) و`__kajSetState()` و`__kajBudget()` |
| `matrix.js` | يشغّل الفاحص على المصفوفة كلها: `__kajMatrix.points()` و`__kajMatrix.sweep()` |
| `check-strings.js` | تغطية ترجمة رسائل الدخول (يُشغَّل بـnode) |

## الاستخدام

1. `node tools/login-check/serve.js` — ثم افتح `http://127.0.0.1:8765/login`.
2. في الكونسول:

```js
const s = document.createElement('script'); s.src = '/matrix.js'; document.head.append(s);
// لكل لغة، وفي الوضعين الفاتح والداكن:
await __kajMatrix.points('ar');   // fails فارغة = سليم
await __kajMatrix.sweep('ar');
```

3. `node tools/login-check/check-strings.js`

المعاينة تجلب HTML الصفحة وحزم الإطار من الموقع الحيّ، وتضع `login.css` (مصغَّراً بما يصغّره به `branding.py` حرفياً) و`login_lang.js` و`pwa.js` وصورة الشعار من المستودع. فما يُفحص هو ما سيراه المتصفح بعد النشر، لا تقريب له.

المعاينة للقراءة فقط: كل طلب غير `GET` يُرفض محلياً ولا يصل الخادم، فلا يمكن لاختبار أن يسجّل دخولاً أو يستهلك حدّ المحاولات. وأصلها (`127.0.0.1`) غير أصل الموقع، فلا تمسّ جلسة مفتوحة عليه في المتصفح نفسه.

## المصفوفة

`points` — تحميل جديد لكل نقطة، وكل الفحوص:

- **المقاسات (21):** `2560×1300` · `1920×950` · `1536×730` · `1440×680` · `1366×650` · `1280×600` · `1260×590` · `1093×510` · `1024×768` · `1023×700` · `768×1024` · `390×844` · `390×664` · `375×553` · `360×640` · `360×560` · `320×568` · وأربعة أقصر من المحتوى: `844×390` · `667×375` · `360×460` · `1093×400`
- **الحالات (6):** الدخول عادياً، وبرسالة فشل (`banner`)، وبأطول رسالة يصدرها الإطار (`long`)، وبتنبيه الحقلين الفارغين (`fields`)؛ ثم «نسيت كلمة المرور» و«الدخول برابط البريد».

`sweep` — تحميل واحد لكل حالة ثم كل ارتفاع بخطوة 2px لـ18 عرضاً: أقصر ارتفاع للمحتوى لا يتجاوز حدّ الاتساع، ومنه حتى 1400px لا تمرير عند أي ارتفاع.

المقاسات بالبكسل المنطقي (CSS)، لا الفيزيائي: شاشة 1920×1080 بتكبير 150% نافذتها نحو `1260×590`، ولابتوب 1366×768 بتكبير 125% نحو `1093×510`، وآيفون SE في سفاري نحو `375×553`. الفحص على نافذة واسعة وحدها يُخفي كل عيوب الارتفاع.

## ما يُفحص

| المعرّف | العيب |
|---|---|
| `OVERFLOW-X` | تمرير أفقي |
| `FITS` | المحتوى أطول من النافذة عند ارتفاع يبلغ حدّ الاتساع (الجدول أدناه) |
| `BUDGET` · `HOLE` | (المسح) أقصر ارتفاع للحالة يتجاوز حدّها · تمرير عند ارتفاع أعلى من ارتفاعٍ اتّسعت فيه |
| `TOUCH` | حقل أو زر أقصر من 44px |
| `INPUT-FONT` | خط الحقل أقل من 16px (يُكبّر iOS الصفحة عند التركيز) |
| `ICON-OVERLAP` / `ICON-SIDE` / `ICON-VCENTER` | أيقونة فوق النص، أو في الجهة الخطأ، أو منحرفة رأسياً |
| `TEXT-CLIP` | نص مقتطع |
| `CONTRAST` | تباين دون WCAG AA، مع احتساب الشفافية — يشمل رسائل الخطأ |
| `MSG-LANG` / `MSG-OUT` / `MSG-CLIP` / `MSG-FONT` / `MSG-EMPTY` | رسالة بغير لغة الصفحة، أو خارج البطاقة، أو مقتطعة، أو بخط دون 12px، أو فارغة |
| `STACK-OVERLAP` | عناصر النموذج يركب بعضها بعضاً حين تُضاف رسالة |
| `ALIGN` / `ALIGN-H4` | التسمية أو العنوان لا يبدآن من حافة الحقل |
| `PANEL` | الشعار الكبير غائب من 1024px فما فوق، أو ظاهر تحتها |
| `ART-OUT` / `ART-SMALL` | الشعار خارج النافذة، أو أصغر من 240px |
| `PANEL-OVERLAP` / `SIDES` | البطاقة تتقاطع مع الشعار، أو أحدهما في غير جهته |
| `SYMMETRY` | مركزا الشعار والبطاقة ليسا على بُعد واحد من منتصف الشاشة |
| `GAP-TIGHT` / `GAP-WIDE` | المسافة بين الشعار والبطاقة دون 40px أو فوق 260px |
| `ART-DOMINANT` | الشعار أعرض من 1.25× عرض البطاقة |
| `CARD-OUT` / `CARD-CLIPPED` | البطاقة خارج النافذة أفقياً، أو مقصوصة من الأعلى |
| `PRIMARY-UNREACHABLE` / `PRIMARY-CLIPPED` | زر الدخول لا يُبلَغ بالتمرير |
| `FIXED-ON-CARD` / `FIXED-ON-ART` | عنصر عائم (مبدّل اللغة، «ثبّت التطبيق») يركب البطاقة أو الشعار |
| `FIXED-OVERLAP` / `FIXED-ON-FIXED` / `FIXED-OUT` | عنصر عائم يغطّي حقلاً أو زراً، أو يركب عائماً آخر، أو يخرج عن الصفحة |
| `STATE` | (المصفوفة) لم تظهر الرسالة المنتظرة في حالة خطأ، أو ظهرت في الحالة العادية |

حين تطول الصفحة عن النافذة تُعاد فحوص العناصر العائمة عند طرفَي التمرير: عنصر ثابت بريء في أعلى الصفحة يصير فوق البطاقة بعد التمرير.

## حدّ الاتساع

أقصر ارتفاع يجب أن تتّسع فيه الصفحة بلا تمرير. مكتوب في `checker.js` (`__kajBudget`) مستقلاً عن `--kaj-fit` في `login.css`: فاحص يقرأ الوعد من الملف الذي يفحصه لا يكشف وعداً تراخى.

| العرض | بلا رسالة | برسالة خطأ |
|---|---|---|
| من 1024px | 480px | 480px |
| 360–1023px | 488px | 572px |
| دون 360px | 524px | 612px |

إن أُضيف للبطاقة محتوى يرفع أقصر ارتفاع فوق هذه الحدود فشل `BUDGET`، والقرار حينها: يُقلَّص المحتوى، أو يُرفع الحدّ هنا و`--kaj-fit` معاً عن علم.

## لماذا المسح لا النقاط وحدها

المسافات الرأسية كانت تتبدّل على درجات (`max-height: 700px` ثم `600px` ثم `560px`) ضُبطت على الحالة العادية في 14 مقاساً، ونجحت فيها كلها. المسح أظهر ما بينها: فوق كل عتبة مباشرة شريط ارتفاعات يظهر فيه تمرير متى ظهرت رسالة خطأ (604–644px و704px تحت 1024px عرضاً). المصفوفة المتفرّقة لا ترى ما بين نقاطها.

## حين يتغيّر الإطار

إن حدّث Frappe صفحة الدخول فشغّل الفاحص على الإطار الخام (بلا تنسيقنا) أولاً: يجب أن **يفشل** (حقول 28px، تباين 4.17). فاحصٌ لا يفشل على الإطار الخام لم يعد يرى شيئاً.

للحقن اليدوي فوق الصفحة الحيّة مباشرة (دون المعاينة) يقدّم `serve.js` الملفات على `/login.css` و`/checker.js`:

```js
const get = u => fetch('http://127.0.0.1:8765' + u).then(r => r.text());
const [css, chk] = await Promise.all([get('/login.css'), get('/checker.js')]);
document.querySelectorAll('#kaj-login-css').forEach(n => n.remove());   // ‎#kaj-login-vars يبقى: فيه رابط الشعار
const s = document.createElement('style'); s.textContent = css; document.head.append(s);
eval(chk);
__kajCheck();
```
