# فحص المكتب (desk-check)

أدوات لفحص واجهة النظام بعد الدخول **قبل** النشر: نسخة اختبار تعمل بكود
المستودع على بيانات الإنتاج، زاحف يفتح كل شاشة، وتجربة تُدخل مستندات حقيقية من
الواجهة. الإنتاج لا يُمسّ في أي خطوة.

## لماذا نسخة اختبار

تغيير في القوائم أو النماذج أو الصلاحيات لا يُعرف أثره إلا على النظام وهو
يعمل. النشر ثم الاكتشاف يعني أن المستخدم هو من يكتشف. نسخة الاختبار موقع ثانٍ
(`kaj-staging.localhost`) على الخادم نفسه، قاعدته نسخة من قاعدة الإنتاج، وكوده
كود المستودع المحلي لا الكود المنشور.

```
المتصفح ──► serve.js (127.0.0.1:8766) ──► نفق SSH (8082) ──► gunicorn الاختبار (8001)
                │                                              └─ PYTHONPATH=/tmp/kaj-overlay
                └─ /assets/khat_workshop/* من المستودع مباشرة      (نسخة من كود المستودع)
```

## التشغيل

```bash
tools/desk-check/staging.sh sync      # ينسخ كود المستودع ويشغّل خادم الاختبار
tools/desk-check/staging.sh setup     # يطبّق خطوات الإعداد كلها (ما يفعله migrate)
tools/desk-check/tunnel.sh &          # نفق يعيد الاتصال تلقائياً
node tools/desk-check/serve.js &      # المعاينة على http://127.0.0.1:8766
```

بعد أي تعديل في بايثون: `staging.sh sync` ثم الخطوة المعنية
(`staging.sh run khat_workshop.setup.workshop_forms.execute`). تعديل JS أو CSS
يكفيه تحديث الصفحة: `serve.js` يقدّم ملفات المستودع.

أوامر أخرى: `staging.sh py` (بايثون من الدخل القياسي داخل نسخة الاختبار)،
`staging.sh sql`، `staging.sh stop`.

**افتح المعاينة في سياق متصفح معزول.** المتصفح المشترك يحمل جلسة صاحب النظام
على الإنتاج.

## الفحوص الثلاثة

### 1. الصلاحيات — من الخادم

```bash
tools/desk-check/staging.sh run khat_workshop.access_test.run
```

لكل مسمّى وظيفي: هل يرى اللوحات السبع، وهل يملك ما يحتاجه عمله. ينشئ مستخدماً
مؤقتاً لكل مسمّى ثم يتراجع عن كل شيء.

### 2. الزحف — كل شاشة تفتحها بلاطة

في المعاينة، بعد الدخول:

```js
const s = document.createElement('script'); s.src = '/__kaj/audit.js'; document.head.append(s);
const results = await __kajAudit.crawl();     // نحو خمس دقائق
__kajAudit.problems(results);
```

`problems` يعيد ما يستحق النظر فقط: شاشة لم تُفتح، خطأ ظهر عند فتحها، جدول
يُمرَّر أفقياً أو أعمدته لا تصطفّ، قائمة بلا عمود إجراءات، ونصوص بقيت
بالإنجليزية مع الشاشات التي ظهرت فيها.

### 3. التجربة — إدخالات حقيقية من الواجهة

```js
const s = document.createElement('script'); s.src = '/__kaj/e2e.js'; document.head.append(s);
await __kajE2E.run('workshop');
```

| السيناريو | ما يفعله |
|---|---|
| `firstday` | على نظام فارغ: فني ← خدمة بسعرها ← قطعة برصيدها ← ثم دورة `workshop` كاملة بها |
| `workshop` | عميل ← مركبة ← بطاقة عمل (يُجلب الاسم والسعر) ← اعتماد يصرف القطع ← عرض سعر ← فاتورة بضريبة 5% ← سند قبض |
| `sales` | عرض سعر مباشر ← فاتورة تصرف من المخزون ← مرتجع يعيد القطعة |
| `purchasing` | مورد ← أمر شراء ← استلام يزيد المخزون ← فاتورة ← سند صرف |
| `stock` | صنف بسعره ← استلام مواد ← صرف مواد |
| `accounting` | قيد يومية متوازن |
| `settings` | إضافة مستخدم بالحوار الواحد، ثم نموذجه |
| `reports` | كل تقرير تعرضه بلاطة: يفتح، له أعمدة، وما بقي من مرشّحاته بالإنجليزية |

كل سيناريو يملأ النماذج بدوالّ النموذج نفسها ويضغط زرّه الأساسي، فتعمل
سكربتات الحقول والتحقق كما تعمل مع المستخدم. يرفض التشغيل على غير نسخة
الاختبار.

## البيانات النموذجية

السيناريوهات (عدا `firstday`) والاختبارات الخادمية تحتاج القطع والخدمات
النموذجية. نسخة الاختبار المستعادة من موقع سُلِّم نظيفاً لا تحملها؛ تُزرع بـ:

```bash
bench --site kaj-staging.localhost set-config kaj_demo_data 1   # ثم staging.sh setup
```

## بأي حساب

**بحساب مدير الورشة، لا Administrator.** Administrator يرى كل شيء ويملك كل
شيء؛ ما يحجبه النظام عن غيره لا يظهر له. الفحوص الثلاثة تُشغَّل مرتين: مرة
بـAdministrator، ومرة بحساب مدير الورشة في سياق متصفح آخر.

## بأي مقاس

نافذة صاحب النظام 1260×590 (شاشة 1920×1080 بتكبير 150%). ما يتّسع على 1500
بكسل ارتفاعاً قد يختفي زرّه الأساسي تحت الطيّ هناك.
